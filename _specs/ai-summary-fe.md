# Spec for ai-summary-fe

branch: claude/feature/ai-summary-fe
ownership: 🤖 AI may implement (`web/` เท่านั้น ห้ามแตะ `api/`)

## Summary
- เพิ่มปุ่ม "สรุปด้วย AI" ในการ์ดคำขอที่ยัง pending ในหน้าจัดการสัตว์ของเจ้าของ (`web/src/pages/ManagePetPage.tsx` → `web/src/features/owner/PetApplicationCard.tsx`)
- เพิ่มปุ่ม "สรุปทั้งหมด" ระดับหน้า ที่สรุปคำขอ pending ทีละใบตามลำดับ และข้ามใบที่มีสรุปแล้ว
- เรียก API ที่มีอยู่แล้ว `POST /applications/:id/summary` ไม่มีการเปลี่ยนแปลงฝั่ง `api/`
- AI สรุปให้อ่านเท่านั้น UI ต้องไม่สื่อว่า AI แนะนำให้อนุมัติหรือปฏิเสธ และต้องมีข้อความกำกับ "สรุปโดย AI ใช้ประกอบการพิจารณาเท่านั้น"
- ข้อความ error เป็นภาษาไทย แปลที่ FE (BE ตอบภาษาอังกฤษ)

## Functional Requirements
- **API endpoint function**
  - เพิ่มฟังก์ชันเรียก `POST /applications/:id/summary` ใน `web/src/lib/api/endpoints.ts` ผ่าน `apiRequest` แบบเดียวกับ `approveApplication` / `rejectApplication`
  - เพิ่ม type ของผลลัพธ์ใน `web/src/lib/types.ts`: summary มี `overview` (string), `highlights` (string[]), `concerns` (string[]) และ `updated_at` (string)
- **Hook (TanStack Query)**
  - ใช้ `useMutation` ตาม pattern ใน `web/src/features/owner/use-owner-actions.ts` (ไฟล์ hook อยู่ใน `web/src/features/owner/`)
  - ผลสรุปของแต่ละคำขอต้องเก็บไว้ในที่ที่ทั้งการ์ดและปุ่ม "สรุปทั้งหมด" อ่านได้ร่วมกัน (เช่น query cache ด้วย key ใหม่ใน `web/src/lib/query/query-keys.ts`) เพื่อให้ "สรุปทั้งหมด" รู้ว่าใบไหนมีสรุปแล้ว และการ์ดแสดงผลที่ได้จาก "สรุปทั้งหมด" ได้
  - การสรุปไม่เปลี่ยนสถานะคำขอหรือสัตว์ จึงไม่ต้อง invalidate รายการคำขอหรือข้อมูลสัตว์หลังสำเร็จ
- **ปุ่ม "สรุปด้วย AI" ใน `PetApplicationCard`**
  - แสดงเฉพาะการ์ดที่ `status === 'pending'` เท่านั้น
  - ใช้ไอคอนจาก `lucide-react` (มีอยู่แล้วใน `web/package.json`) ห้ามใช้ emoji
  - วางแยกจากปุ่มอนุมัติ/ปฏิเสธให้เห็นชัดว่าเป็นตัวช่วยอ่าน ไม่ใช่ปุ่มตัดสิน
- **สถานะของการ์ด (4 สถานะ)**
  - ยังไม่กด: แสดงปุ่ม "สรุปด้วย AI"
  - กำลังโหลด: ปุ่ม disabled พร้อมข้อความ/ไอคอนบอกว่ากำลังสรุป
  - สำเร็จ: แสดง `overview`, หัวข้อ highlights และ concerns เป็นรายการ ถ้า array ไหนว่างให้ซ่อนทั้งหัวข้อ แสดงข้อความกำกับ "สรุปโดย AI ใช้ประกอบการพิจารณาเท่านั้น" เสมอ ไม่ต้องแสดงปุ่มสรุปซ้ำ
  - ล้มเหลว: แสดงข้อความไทยตามชนิด error (ในการ์ด ไม่ใช่แค่ toast) พร้อมปุ่ม "ลองใหม่"
- **ข้อความ error ภาษาไทย**
  - ใช้ `getErrorMessage` ใน `web/src/lib/api/errors.ts` ร่วมกับ `overrides` ตาม status สำหรับ endpoint นี้ เพราะค่าเริ่มต้นของ `getErrorMessage` ตีความ 502/504 เป็น "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้" ซึ่งไม่ตรงกับความหมายของ endpoint นี้
  - 403: ไม่ใช่เจ้าของโพสต์
  - 404: ไม่พบคำขอนี้
  - 409: คำขอนี้ถูกตัดสินไปแล้ว (ไม่ใช่ pending)
  - 502: AI ตอบกลับในรูปแบบที่อ่านไม่ได้ ให้ลองใหม่
  - 503: บริการ AI ใช้ไม่ได้ชั่วคราว ให้ลองใหม่ภายหลัง
  - 504: AI ใช้เวลานานเกินไป ให้ลองใหม่
  - Network error และ error อื่นใช้ข้อความเดิมของ `getErrorMessage`
- **ปุ่ม "สรุปทั้งหมด" ระดับหน้า**
  - อยู่ในส่วนหัว "คำขอรับเลี้ยง" ของ `ManagePetPage` แสดงเมื่อมีคำขอ pending อย่างน้อย 1 ใบที่ยังไม่มีสรุป
  - เรียกทีละใบตามลำดับที่แสดงในหน้า รอใบก่อนจบก่อนเริ่มใบถัดไป ห้ามยิงพร้อมกัน
  - ข้ามใบที่มีสรุปแล้ว และใบที่กำลังโหลดอยู่จากการกดในการ์ด
  - ระหว่างทำงาน ปุ่ม disabled และแสดงความคืบหน้า (เช่น "กำลังสรุป 2/5")
  - การ์ดแต่ละใบแสดงสถานะของตัวเอง (โหลด/สำเร็จ/ล้มเหลว) ระหว่างที่ "สรุปทั้งหมด" ทำงาน
  - ใบหนึ่งล้มเหลว → ทำใบถัดไปต่อ ยกเว้น 503 (AI ใช้ไม่ได้ทั้งระบบ) ให้หยุดทั้งชุดและแจ้งผู้ใช้
- **การปิดปุ่มระหว่างทำงาน**
  - ไม่ปิดปุ่มอนุมัติ/ปฏิเสธระหว่างสรุป เพราะการสรุปไม่เปลี่ยนข้อมูล
  - ปุ่มสรุป (ทั้งในการ์ดและ "สรุปทั้งหมด") disabled ตอน `actions.isBusy` (มีการอนุมัติ/ปฏิเสธ/ปิดโพสต์รออยู่)
- **การแสดงผล**
  - ส่วนสรุปแสดงค้างไว้ ไม่มีปุ่มพับ/ซ่อน
  - ไม่แสดงเวลาที่สรุป (`updated_at`)

## Possible Edge Cases
- เจ้าของอนุมัติ/ปฏิเสธใบหนึ่งระหว่างที่ "สรุปทั้งหมด" ทำงาน: คำขออื่นอาจกลายเป็น rejected → ใบที่เหลือได้ 409 หรือหายจากรายการ pending ต้องไม่พังและหยุดข้ามใบที่ไม่ใช่ pending แล้ว
- ผู้ใช้ออกจากหน้าระหว่าง "สรุปทั้งหมด": ต้องไม่ setState บน component ที่ unmount แล้ว และไม่ควรยิงใบที่เหลือต่อ
- กดปุ่มในการ์ดซ้ำเร็ว ๆ: ปุ่ม disabled ระหว่างโหลด จึงยิงได้ครั้งเดียว
- โหลดหน้าใหม่: รายการคำขอจาก `GET` ไม่มีข้อมูลสรุป จึงกลับไปสถานะ "ยังไม่กด" แต่กดใหม่จะได้ผลเดิมทันทีจาก BE (ไม่เสียโควตา AI)
- AI ตอบ `highlights` และ `concerns` ว่างทั้งคู่: แสดงแค่ overview และข้อความกำกับ
- ข้อความสรุปยาว: ต้องตัดบรรทัดได้ (`break-words`) ไม่ล้นการ์ดบนมือถือ
- 504 อาจมาจาก proxy (Vite dev / hosting) ที่ติดต่อ API ไม่ได้ ไม่ใช่ AI ช้า — ยอมรับได้ว่าข้อความจะบอกว่า "ใช้เวลานาน ลองใหม่" ทั้งสองกรณี
- สัตว์ไม่ใช่ available (ปิดโพสต์แล้ว) แต่ยังมีคำขอ pending: ยังสรุปได้ เพราะ BE เช็คแค่สถานะคำขอ

## Acceptance Criteria
- การ์ด pending มีปุ่ม "สรุปด้วย AI" พร้อมไอคอน lucide การ์ดที่ไม่ใช่ pending ไม่มีปุ่มและไม่มีส่วนสรุป
- กดแล้วปุ่ม disabled ระหว่างโหลด สำเร็จแล้วแสดง overview, highlights, concerns (ซ่อนหัวข้อที่ว่าง) และข้อความ "สรุปโดย AI ใช้ประกอบการพิจารณาเท่านั้น"
- เมื่อ API ตอบ 403/404/409/502/503/504 การ์ดแสดงข้อความไทยที่ตรงกับแต่ละกรณี พร้อมปุ่ม "ลองใหม่" ที่กดแล้วเรียกใหม่ได้
- "สรุปทั้งหมด" ยิง request ทีละใบ (ตรวจใน Network tab ว่าไม่มี request ซ้อนกัน) และไม่ยิงใบที่มีสรุปแล้ว
- ใบหนึ่งล้มเหลวระหว่าง "สรุปทั้งหมด" การ์ดใบนั้นแสดง error ส่วนใบอื่นยังทำงานต่อ ยกเว้น 503 ที่หยุดทั้งชุด
- ระหว่างสรุป ปุ่มอนุมัติ/ปฏิเสธยังกดได้ และปุ่มสรุป disabled ตอนมีการอนุมัติ/ปฏิเสธ/ปิดโพสต์รออยู่
- ไม่มีไฟล์ใดใน `api/` ถูกแก้ไข
- `npm run build` และ `npm run lint` ใน `web/` ผ่าน

## Testing Guidelines
List the test cases only.
- `web/` ยังไม่มี test runner (ไม่มี script `test` ใน `web/package.json`) รอบนี้จึงทดสอบด้วยมือในเบราว์เซอร์
- การ์ด pending แสดงปุ่ม "สรุปด้วย AI" การ์ด approved/rejected/withdrawn ไม่แสดง
- กดสรุปสำเร็จ → แสดง overview, highlights, concerns และข้อความกำกับ
- ผลที่ highlights หรือ concerns ว่าง → หัวข้อนั้นถูกซ่อน
- จำลอง 502/503/504 (เช่น ตั้ง `AI_MODEL` ใน env ของเครื่องตัวเองให้ผิด หรือปิดเน็ตระหว่างเรียก) → ข้อความไทยตรงชนิด และปุ่ม "ลองใหม่" ทำงาน
- 409: เปิดสองแท็บ ปฏิเสธในแท็บหนึ่ง แล้วกดสรุปอีกแท็บ → แสดงข้อความ "คำขอนี้ถูกตัดสินไปแล้ว"
- "สรุปทั้งหมด" กับคำขอ 3 ใบที่ 1 ใบมีสรุปแล้ว → ยิง 2 request ตามลำดับ ไม่ซ้อนกัน
- ออกจากหน้าระหว่าง "สรุปทั้งหมด" → ไม่มี warning ใน console และไม่ยิงใบที่เหลือ
- หน้าจอมือถือ: ส่วนสรุปและปุ่มไม่ล้นการ์ด
